# SnapColor Engine 架构

## 1. 数据流

```text
目标图像RGB
  → 标准色彩转换（Lab）
  → profile配方目录
  → 每像素Top-K候选
  → 确定性空间优化
  → 小区域制造性清理
  → 配方图
  → 层号×材料掩膜
  → 后续独立网格/3MF适配器
```

## 2. 模块边界

- `color/`：只实现公开色彩标准；
- `profile/`：格式验证、材料和实测样本索引；
- `recipes/`：与具体打印机无关的有序配方空间；
- `predictors/`：模拟、实测和未来物理模型的可替换接口；
- `optimizer/`：感知色差与空间制造性优化；
- `layers/`：把最终配方编译为材料层掩膜；
- `calibration/`：生成自主校准实验的排盘清单；
- `compiler/`：端到端编排，不包含UI和厂商模板。

## 3. profile等级

- `simulation-only`：仅供软件开发；
- `measured-prototype`：已有自主实测，但设备/重复性未达正式门槛；
- `validated`：拥有完整来源、重复性和留出验证报告。

引擎不会把模拟 profile 自动升级为实测或正式 profile。

## 4. 预测策略

V1正式制造只使用实测离散配方。模拟预测器使用简单、可解释的线性光叠加，只用于在打印实验之前验证端到端流程。未来的K/S、光谱或学习模型必须实现同一预测器接口，且不得覆盖原始实测值。

## 5. 四色系统的光学基色约束

引擎把结构基材、反射背衬和光学基色分开建模。四色配方可以指定一卷材料为光学基色，并设置：

- 固定层位；
- 最少出现层数；
- 是否允许在其他层继续出现。

配方生成器在递归枚举过程中直接应用约束。例如5层四色系统将最靠近背衬的一层固定为白色后，搜索空间从 `4^5=1024` 降为 `4^4=256`。这同时减少校准色块、配方匹配和实际换料复杂度。层索引始终从观看面开始，避免面朝下打印时混淆物理打印顺序和观看顺序。

在完整配方目录可用时，`rankOpticalBaseCandidates` 可以针对目标图分别评估不同基色。评分同时考虑：

- 目标图的平均与最大 ΔE00；
- 该基色约束下仍可使用的配方数量；
- 实际选中配方的平均材料切换次数。

模拟profile只能用于决定“优先打印哪组基色实验”，正式基色结论必须由同条件实测目录重新排名。

## 6. 确定性

相同的：

- 输入像素；
- profile内容；
- 优化参数；
- 引擎版本；

必须得到相同配方图。当前算法不使用随机初始化，便于复现、审计和专利材料留档。
