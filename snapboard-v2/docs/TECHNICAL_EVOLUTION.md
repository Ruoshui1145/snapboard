# SnapBoard 技术创新与迭代路径

更新时间：2026-09-25

本文回答三个问题：SnapBoard 的技术难点是什么、代码是怎样逐步解决的、哪些结果可以作为科创证据。除“当前实现”外，所有未来内容都明确标记为规划或实验，不把路线图当成已完成能力。

## 1. 总体技术路线

```text
2D 草图与尺寸约束
        ↓
轮廓归一化、外轮廓/内孔识别
        ↓
原始轮廓唯一长孔母阵 + 可制造分割规划
        ↓
SplitPanel（真实轮廓、孔位、接缝、热床角度）
        ↓
Three.js Shape/Path → ExtrudeGeometry
        ↓
3D 视口、配件锚点、正背面装配、纹理层
        ↓
3MF 多盘、闭合网格、Bambu 实例与工艺参数校验
```

SnapBoard 的核心不是单独的画图器或渲染器，而是让同一份毫米几何在 2D、分割、3D 装配和 3MF 制造之间保持不变量：轮廓不变、孔位语义不变、板厚不变、制造网格可验证。

## 1.1 工作台 UI 与可用性演进（当前实现）

UI 也遵循“状态可解释、内容可到达”的工程原则：

- 分割参数配置从结果吸顶层移出，结果摘要与警告才使用独立覆盖层；因此展开大量参数不会把板件列表推到不可见或形成嵌套滚动；
- 配件库用 IntersectionObserver 观察 24px 置顶哨兵，向下滚动后收拢为单行“当前分类 / 搜索 / 工具”，回到顶部自动展开；大类/细分下拉避免标签裁切，也不使用 scroll 事件每帧触发渲染；
- 1024px 以下右栏转为覆盖式抽屉，主画布保持至少 480px 的内部工作宽度；侧栏宽度按视口分档并在 resize 时重新约束；
- 画布操作提示改为 DOM `role=status`，首启清单和上下文提示使用 localStorage 可关闭，不做强制模态巡演；
- 统一玻璃层 token，覆盖滚动内容的吸顶/吸底层保持高不透明度；配件吸附、板件渐入和提示动效在 `prefers-reduced-motion` 下关闭。

这些改动的验收入口是 `npm run verify:ui-layout` 和真实浏览器冒烟；布局回归不能由几何脚本代替。

## 1.2 从屏幕编号到制造内生的装配标识（2026-09-04）

早期 `makePanelLabel()` 只在 Three.js 正面显示 Sprite，既不会进入 3MF，也不能解决打印完成后的板件混淆。本轮把装配身份提升为制造数据：最终 `SplitPanel[]` 先建立共享边邻接图，稳定生成全局 P 板号和 J 接缝关系；实体接缝只显示两侧同位置、面对面的短数字箭头，完整板号关系留在 UI/3MF 装配表。正面 Sprite 同时启用深度遮挡，禁止从背面或自由视角穿透板体。

最初尝试把 5×7 字形的数百个小矩形直接作为背面薄层孔环；在规则孔阵板上，earcut 会因大量共线微孔出现 T 型三角边，双板测试产生 116–384 条异常边。最终改为“每组文字只扣一个浅凹底框，字形作为同材质闭合小实体齐平填回”，既保持背面不凸出，也把负轮廓数量降到每组一个。制造失败仍按单板回退，不取消原有闭合网格闸门。

该链路同时修复了对象复用语义：原 `panelSignature()` 有意忽略 `panel.id`，尺寸与孔位相同的板可复用一个 3MF object；永久编号出现后必须把标识签名加入 key，否则多块板会打印相同编号。实现与测试详见 [`BACK_ASSEMBLY_MARKING.md`](BACK_ASSEMBLY_MARKING.md) 和 `verify-assembly-marking.mjs`。

接缝标识经历了“`J02-P01` 长串放在板内 → 贴边短数字 → 大号优先的贴边短数字”三次调整。最终做法不要求用户记住板号：两个同号三角箭头位于接缝两侧同一投影位置并面对面；规划器沿整条接缝搜索共同孔隙，优先使用4.2mm数字/4.0mm箭头，失败后才降为中号或小号。完整J/P关系只进入界面和assembly-map。

制造成功与视觉可见也必须分开判断。标识与基材同耗材，在切片器的耗材着色下不会呈现第二种颜色；普通板应检查底面/首层，装饰面朝热床的复合板应检查顶面/末层。导出汇总通过 `markingAppliedCount/markingRequestedCount` 给出制造事实，对象名只有实际网格成功才带“背面凹刻”，不能用“可能是视角问题”掩盖安全回退。

接入 UI 后还暴露出一次 React 19 状态快照问题：在 Zustand selector 内以 `?? []` 回退会在无分割结果时不断生成新引用。取消分割将 `splitResult` 设为 `null` 后，React 进入无限被动更新并卸载整棵应用，外观即“自动分割后白屏”。修复原则是 selector 只返回 store 中的稳定引用，空数组在组件模块级复用；`verify-assembly-marking.mjs` 固化了禁止 selector 内分配空数组的检查。

## 1.3 切片盘名与板号同源（2026-09-25）

装配标识做到制造内生之后，仍有一处身份信息游离在体系外：3MF 在切片软件里的盘名（`plater_name`）一直按盘序编「SnapBoard 板件 第 N 盘」。盘序是排盘结果，P 编号是几何顺序，两者只在"每盘恰好装一块板"时偶然一致；一盘装不下整单板件时必然错位——盘 1 可能装 P01 和 P02 各一部分，盘 2 才是 P03。用户拿着背面刻着 P01 的板子，在切片软件的"第 1 盘 / 第 2 盘"里找不到确定的对应关系，配件盘号同样与任何编号都对不上。

修复原则与 §1.2 相同：凡是给人看的板件身份，都必须来自 `stablePanelIds()` 这同一个来源。盘名改为从盘内实例对象名提取 P 编号——板件盘 `SnapBoard 板件 P01`（一盘多板用「、」连接），配件盘只叫 `SnapBoard 配件`（多盘才补序号），试样盘保持「试样（先打印）」并去掉盘序。至此切片盘名、板件背面刻字、逐板导出文件名三处身份必然一致，不再存在"第几盘"这套会漂移的平行编号。该行为由 `verify:native-process` 的盘名回归断言锁定；旧文件无法追溯修复，只能重新导出。

## 2. 自动分割算法的演进

### 阶段 A：简单矩形/孔间中线原型（历史兼容）

早期 `src/utils/split.ts` 的 `autoSplit()` 只接收宽高、孔距和最大板尺寸，沿孔间中线贪心放置水平/竖直切线。它适合说明“切线不穿孔”的基本想法，但不能表达 L/U/缺口/梯形、内孔、热床禁放区和真实板件轮廓。

该文件保留作兼容参考，不是当前自动分割的权威实现。当前入口是 `src/utils/pegboardSplit.ts`。

### 阶段 B：栅格区域 + 最大合法矩形

`pegboardSplit.ts` 首先把外轮廓离散为 1 mm 材料掩膜，以 `Region` 表示连通材料。每轮从区域中寻找面积最大的合法矩形，要求：

- 宽高满足热床有效区域和禁放区；
- 内孔安全包围盒不被接缝切穿；
- 锚点沿 `mx/my` 模数线，尽量落在孔间；
- 剩余碎料尝试并入共享边最长的相邻板。

这一阶段解决了“异形轮廓不能只按包围盒裁矩形”的问题，但面积贪心会把余量集中成细长条，也容易让规则矩形出现视觉错位。

### 阶段 C：覆盖优先、边界融合与 Worker

随后加入 `regionBoundaryLoops()`、`mergeRegions()`、精确轮廓回裁和 `exactCoverTiles()`：

1. 栅格只用于规划接缝，最终板件再与原始矢量轮廓做布尔相交；
2. L 型、阶梯型等相邻区域可在热床允许时融合为一个真实异形板；
3. 斜边不再被静默栅格化或丢弃，覆盖率不足时切换完整覆盖路径；
4. `regionRightRuns`、边界缓存、打印角度缓存和 Worker 降低大板计算的主线程阻塞。

这一步使算法从“几何演示”进入“制造输出”：`SplitPanel.contour` 是实际外轮廓，`cutouts` 是真实内孔/缺口，覆盖率和警告成为输出的一部分。

### 阶段 D：fat partition 与特征对齐（当前实现）

针对 20 mm 细长补偿条和矩形错位，当前增加了两类候选：

- **平衡模数网格**：枚举行列数，以无细条、板数、最短局部结构宽度、接缝长度和长宽比排序；
- **特征对齐网格**：把轮廓凹角/转折点作为候选切线，避免切线贴着转折点留下窄颈。

1 mm 掩膜上的横向/纵向连续材料带用于估计局部最小结构宽度；`minFeatureWidth` 默认 60 mm，低于它不再静默输出，而是给出制造警告。500×280 mm 矩形现在稳定为 3×2 对齐网格，不再产生 20×220 mm 独立细条。

这一设计对应计算几何中的 fat rectangle partition 思路：目标不是只追求面积最大或块数最少，而是把“最短边/局部结构宽度”纳入分区质量函数。

### 阶段 E：先母阵、后分割线、再连接圆孔（当前实现）

用户提供的 `四版拼接.DXF` 促成了孔位流程的再次修正。现在严格按以下顺序执行：

1. 以原始轮廓左下角和全局设计坐标建立唯一长孔母阵：A 相 `(10,30)+40n`，B 相 `(30,10)+40n`；
2. 分割算法只决定接缝和板件，不重新为 P1/P2…起孔阵；
3. 每块板从母阵中领取完整落入自身安全域的长孔；
4. 分割线确定后，内部接缝两侧生成连接圆孔；
5. 外周圆孔与最近长孔行/列共线，沿边取相邻长孔中心中点，端部只做半节距外推；
6. 对圆孔做去重、与长孔碰撞、缺口/内孔安全域和 20 mm 最小中心距检查。

因此，标准 400×400 场景会得到四块 200×200 板，每块 50 个长孔和 18 个圆孔；非模数板也不会因每块重新起阵而出现上下重复相位。圆孔制造直径按用户确认固定为 φ5；DXF 中 R3 只用于中心位置提取。

## 3. 3D 引擎的演进

### 阶段 A：二维轮廓直接拉伸

`src/utils/boardMesh.ts` 的第一条稳定路径是：

```text
毫米轮廓 → THREE.Shape
孔位 → THREE.Path（长孔/圆孔/内孔）
Shape.holes → THREE.ExtrudeGeometry
```

它避免了高开销的 3D 布尔，适合洞洞板这种“平面孔 + 固定厚度”的结构。孔在 Shape 层作为真正贯通路径，预览虚线不进入实体网格。

### 阶段 B：分割板件真实外轮廓

随着自动分割输出 `SplitPanel.contour`，`createSplitPanelShape()` 和 `generateSplitPanelMesh()` 统一处理：

- 正交异形外轮廓和整体外露凸角圆角；
- 接缝内角保持直角，保证板件拼合平齐；
- 长圆孔、φ5 圆孔和内孔作为贯通 Shape 路径；
- 预览曲线精度与制造导出曲线精度分离；
- 倒角向轮廓内收，不能让制造实体越过设计外壁。

这样 2D 轮廓、3D 预览和 3MF 制造网格不再各自近似一遍。

### 阶段 C：场景、相机和可视化反馈

`src/components/viewport/Viewport3D.tsx` 从“显示一个板”扩展为完整工作区：

1. 初始化 Three.js Scene、PerspectiveCamera、WebGLRenderer；
2. 使用 `OrbitControls` 支持旋转、缩放和屏幕平移；
3. 使用 `EffectComposer + OutlinePass + OutputPass` 提供选择高亮和色彩输出；
4. 统一 sRGB 输出与 ACES 色调映射，避免不同材质/浏览器颜色漂移；
5. 分割布局变化时自动取景，用户仅切换贯通孔状态时不抢夺相机；
6. 使用 Raycaster 把鼠标/触摸位置映射到板面，支持配件拖放和纹理直接操作。

### 阶段 D：配件装配与可解释吸附

`glbLoader.ts`、`assemblySnap.ts`、`assemblySide.ts` 和 `mountAxis.ts` 把 3D 引擎从“看模型”变成“验证装配”：

- 支持 STL、3MF、GLB、GLTF，并保留可用的原生多材质；
- 通过 `renderNode` 处理挂钩/托盘等多对象模型；
- 以长孔轴向、圆孔、接触面 `contactZ` 和默认朝向描述零件，而不是靠模型缩放凑孔距；
- 正面/背面装配共享孔位占用集合；
- 拖动时同时显示半透明模型、胶囊/圆形锚点、兼容孔和拒绝原因；
- 命中候选圆孔时执行幂等 `openEdgeHole`，不会重复开孔。

这条路径的创新候选是“几何锚点 + 物理接触面 + 孔位占用”的可解释装配，而不是黑盒最近点吸附。

### 阶段 E：纹理与复合制造层

纹理工作室将板件外观分成贴图纹理、材质贴面和 SnapColor PETG 光学叠色。`boardTexture.ts` 负责图片映射与板件掩膜，`snapColorLut.ts` 负责颜色/耗材配方；3D 中的父对象移动和 3MF 中的 `<components>` 绑定保持一致。

当前制造层明确区分：结构基材、承托/贴面层和光学叠色层。渲染材质、虚线边框、标签和相机信息只存在于预览，不写入制造实体。

### 阶段 F：从网格到可验证制造文件

`export3mf.ts` 将板件/配件分组、按热床排盘，并完成：

- 真实制造网格归一化；
- 每条无向边必须恰好被两个三角形使用的闭合检查；
- 重复模型 object 复用与数量实例；
- Bambu `plater_id = 1..N` 连续映射；
- 纹理复合板父对象整体移动、子零件独立工艺；
- 导出进度、取消和制造警告。

## 4. 当前创新候选与证据边界

| 候选点 | 当前可证明内容 | 不能过度宣称 |
|---|---|---|
| 母阵驱动的分割 | 长孔先生成一次，分板只裁取；非模数分板无重复相位 | 不能称为已证明的全局最优分割 |
| fat partition 分区 | 规则网格、转折点对齐、最小结构宽度和确定性回归 | 60 mm 不是所有 PETG 工况的强度标准 |
| 安全域孔位 | 胶囊/圆与边界距离、缺口删孔、圆孔去重和最小间距 | 没有拉剪/弯曲试验就不能宣称结构强度提升 |
| 2D/3D/3MF 单一几何链 | 同一 `SplitPanel` 驱动 Shape、视口和导出 | Three.js 本身不是 SnapBoard 的自主创新 |
| 可解释配件吸附 | 轴向、contactZ、占孔和正背面状态有明确数据字段 | 不能宣称自动装配覆盖所有零件 |
| 复合纹理制造 | 预览、基层、表层和光学层分别验证并绑定 | 颜色一致性仍需打印样本与测色 |

专利/软著/论文准备时，应把“自研的几何约束、数据流和工程组合”与 React、Three.js、Planegcs、polygon-clipping、fflate 等第三方依赖分开描述，并先做现有技术检索和导师/知识产权指导。

## 6. 材料力学与耐久验证接口

几何回归只能证明“没有相交、覆盖完整、能放入热床”，不能证明板件在宿舍长期受载下足够坚韧。PETG/FDM 的打印方向、层间结合、孔周净截面、环境和时间都会影响结果；材料卡片、孔阵试样、真实接缝和蠕变/循环试验必须先建立，再把 `minLigamentMm`、`seamClearanceMm`、`holeDensity` 和 `riskLevel` 反馈给分割评分。

完整的试样、标准、测量和 Go / Adjust / Stop 门槛见 [`MECHANICAL_VALIDATION_PLAN.md`](MECHANICAL_VALIDATION_PLAN.md)。当前 3D 引擎可以承担几何风险可视化，但尚未内置有限元求解器；在没有真实载荷数据前，不能把算法输出描述成强度保证。

## 7. 后续迭代顺序

### 近期：冻结标准与可解释报告

- 把“母阵 → 分割线 → 圆孔”的中间结果以调试图层显示；
- 在分割结果卡片显示长孔母阵数量、裁取数量、删孔数量、圆孔去重数量和警告原因；
- 对每次算法改动保存输入轮廓、配置、输出 JSON、耗时和截图。

### 中期：手动模块化搭板

先实现矩形模块的点击铺设、边缘吸附、阵列/棋盘材质和半格错位，把手工布局保存为显式约束。它与自动分割互补，可直接成为竞赛展示的“参数化构建模式”。

### 后期：高密度孔阵与六边形实验

先用有限元和 PETG 实物验证孔率、节距、接缝和载荷，再决定是否新增高密度预设。六边形需要新的边连接、轴坐标、任意角度孔位和边界裁切，必须保持实验模式，不应直接替换默认矩形/异形流程。
