# SnapBoard 配件资源包目录

这里类似 Minecraft `mods` / `resourcepacks` 的目录。**每个一级子文件夹是一个可独立复制/分享的资源包**。

## 目录布局

```text
配件资源包/
├── 01-挂钩类/         ← 大类目录：直接把模型文件拖入即可自动收录（也可投递到子文件夹）
├── 02-支架托架类/
├── 03-搁板层板类/
├── 04-收纳容器类/
├── 05-整理件类/
├── 06-紧固锁扣类/
├── 07-底座安装类/
├── 08-线缆整理类/
├── 官方基础配件包/     ← 传统资源包（含 pack.json, 社区分享用）
├── 我的配件/           ← 网页右上角导入的模型（默认归类到这里）
└── _社区资源包模板/
```

## 三种添加配件的方式

1. **文件管理器拖入（后端批量收录）**：把 `.3mf / .stl / .glb / .gltf` 直接拖进
   `配件资源包/<大类文件夹>/`（或其中的子文件夹）。开发服务器监听到文件变化后自动：
   - 为该大类生成/复用 `pack.json`；
   - 每个模型生成一个零件目录（缺省目录名 = 文件名），并补写 `part.json`（待标定）；
   - 重新同步网页配件库，模型立刻出现在对应分类下。
2. **网页多选/拖放导入（前端批量导入）**：配件库面板的导入区支持一次选择/拖入多个
   模型，弹窗里选择大类后批量写入对应大类文件夹（或“我的配件”）。
3. **传统资源包**：`官方基础配件包/parts/<零件>/`（含手写 `part.json`），可整包分享。

网页端每张零件卡右侧的设置按钮可修改名称、说明、资源序号和所属大类，也可以永久删除该零件。默认排序字段为 `part.json.sortOrder`；拖动卡片左侧的 ⠿ 手柄后，顺序会写回资源文件，因此打包、换电脑或重新同步后不会丢失。移动分类会连同整个零件目录一起移动，模型、预览图与标定数据保持成组。

## 大类目录命名规则（自动归类依据）

文件夹名按 「NN-中文名称」 组织，系统按关键词自动判定配件大类：

| 文件夹 | 大类 id | 关键词 |
|---|---|---|
| 01-挂钩类 | hook | 挂 |
| 02-支架托架类 | bracket | 支架/托架/角铁/横杆 |
| 03-搁板层板类 | shelf | 搁板/层板/置物 |
| 04-收纳容器类 | bin | 收纳/容器/盒/杯/桶/篮/托盘 |
| 05-整理件类 | organizer | 整理/钥匙/纸巾/瓶罐 |
| 06-紧固锁扣类 | fastener | 紧固/锁扣/卡扣/螺丝/橡胶 |
| 07-底座安装类 | base | 底座/安装/墙面/连接 |
| 08-线缆整理类 | cable | 线缆/电线/走线/理线 |
| 自定义 | custom | 其他（网页导入时选择“自定义”落到“我的配件”） |

## 导入后需要做的

模型第一次出现在网页后，在配件卡片右侧点击 `⚙`：

1. 确认默认朝向；
2. 选择“长圆孔”或“圆孔”；
3. 依次点击模型上安装柱的平端面；
4. 保存标定。

标定器会把端面中心、端面法向、孔型和默认朝向写回 `part.json`。这些数据随大类目录/
资源包一起导出，其他用户导入后不需要重新标定。`sortOrder` 只控制资源库显示次序，不参与装配求解。

## 社区包导出/导入

- 导出整包：`npm run pack:export -- "官方基础配件包"`（生成 `.sbpack`，本质 ZIP，只允许 JSON/3MF/STL/GLB/GLTF/STEP/图片，不允许脚本）；
- 导入社区包：`npm run pack:import -- "D:/下载/xxx.sbpack"`；同名包不会自动覆盖。
